# 实验方法与消融协议

本文件规定"怎么跑实验、怎么判定有效、怎么记录"。目的是避免用一次好结果下结论，也避免先写故事再凑实验。

## 一、顺序

1. **先跑通一个简单基线**：最小配置 + 固定切分 + 完整评估口径，先把指标和流程稳住。
2. **稳定后再加模块**：每次只动**一个变量**（或明确的一组），其余全部保持不变。
3. **每个配置跑多个种子**：只报均值与方差，不报单次最好结果。
4. **记录三件套**：数据划分、超参数、代码版本，与结果一起写入 `ledger.json`。
5. **最后写成果**：先列结论与图表，再组织故事；引言最后写。

## 二、什么算"基线稳住"

跑消融之前，下面四条必须已经确定，并且在全部实验里保持不变：

| 项 | 要求 |
| --- | --- |
| 切分 | 按患儿（以及按中心，若有）隔离，划分文件哈希固定 |
| 标签口径 | 单一来源与单位，例如 CAMUS 报告 EF，单位 EF 百分点 |
| 评估口径 | 主指标 MAE，同时给 r 与 AUROC（EF 阈值取 50%）；含常数基线对照 |
| 运行口径 | 固定轮数、批大小、优化器与校准方式；至少 3 个随机种子 |

基线未稳就加模块，等于把多个变量混在一起动，后面的结论全部作废。

## 三、消融规则

- **一次只改一个键**。改两个就要拆成两组实验，或明确写成"组合改动"并单独标注。
- **每个配置至少 3 个种子**，比较用均值±方差。
- **判定门槛**：新配置的均值改善必须大于**种子标准差的两倍**，否则写"无显著差异"，不写成"提升"。
- **负结果照写**。消融最常见的产出是"没有差别"，这同样是有用的结论。
- **不许挑种子**。种子列表在跑之前写进 `ledger.json`，跑完不得更换。

## 四、怎么跑

```powershell
$python = '.\.venv\Scripts\python.exe'

# 1) 基线：同一配置跑 3 个种子
& $python -X utf8 .\scripts\experiment.py baseline `
  --emb '.\work\emb' --out '.\runs\exp\base' --seeds 0,1,2 --epochs 80

# 2) 消融：只改 layers，其余沿用基线
& $python -X utf8 .\scripts\experiment.py ablate `
  --emb '.\work\emb' --out '.\runs\exp\layers' --seeds 0,1,2 --epochs 80 --vary layers=1,2
```

`experiment.py` 会：

- 按种子逐个调用 `train_emb_head.py`，已存在的运行直接复用（可断点续跑）；
- 聚合成均值±方差并打印可直接粘进文档的表格；
- 写 `ledger.json`：`manifest` 记录代码 commit 与是否有未提交改动、切分规模与切分哈希、Python / torch / 设备、平台；`args` 记录全部超参数；`results` 记录每个配置每个种子的完整指标。

`--vary` 只允许改动基线里的一个键，这是硬约束，避免"顺手改了学习率"。

## 五、记录与追溯

| 要记的 | 落在哪里 |
| --- | --- |
| 数据划分 | `ledger.json → manifest.data`（规模 + `split_sha256`） |
| 超参数 | `ledger.json → args` 与每个 run 的 `test.json` |
| 代码版本 | `ledger.json → manifest.git`（commit + dirty 标记） |
| 环境 | `ledger.json → manifest.env` |
| 对外数字 | [rules/metrics.json](../rules/metrics.json) 的 `reports` 与 `claims` |

`dirty: true` 的运行不能作为对外数字的来源——代码当时有未提交改动。

## 六、写作顺序

写结论时按这个顺序，不要反过来：

1. **结论表**：每个配置的均值±方差、样本量、单位。
2. **图**：消融曲线（一个变量 vs 主指标，带误差条）、误差分布、失败案例。
3. **判定**：哪些改动有效（超过两倍种子标准差），哪些无差别。
4. **故事**：从上面的结论往回组织动机与方法，引言最后写。

先写引言再凑实验，最后一定是"实验刚好支持了想说的话"。先出结论再写引言，才能写出"我们发现 X 不成立"。

## 七、当前基线状态

| 项 | 状态 |
| --- | --- |
| 基线配置 | 阶段二注意力头，`dim-model 256 / layers 2 / epochs 80 / batch 32 / lr 1e-3` |
| 切分 | CAMUS 官方留出折，494 段 / 247 患儿，按患儿隔离 |
| 种子 | 0、1、2（见 Release `emb-head-camus-v1`） |
| 常数基线 | 已记录，作为"模型有没有学到东西"的下限 |
| 已做的消融 | `layers` 1 vs 2、每视频 clip 数 8 vs 16（结论均为无显著差异） |

**复现性已核对**：用 `experiment.py baseline` 以同一配置重跑三个种子，结果与先前手工运行逐位一致，说明在这台 CPU 上同种子可复现。跨机器或换 `torch` 版本后须重新核对，不能默认一致。

基线结果本身记录在 [EMBEDDING_PIPELINE.md](EMBEDDING_PIPELINE.md) 的表格与 Release `emb-head-camus-v1` 中，本文件不重复数字。

下一步消融建议按这个顺序，一次一个：`dim-model` → `lr` → `epochs` → 每视频 clip 数 → 是否加校准。每项都用 `experiment.py ablate` 跑，不手工改脚本。
