# 脉率采集：器件限制、算法与实测（issue #3）

## 一、先说清楚器件为什么做不了

套件里和"心跳"沾边的只有 **ITR9909**（反射式红外对管 + LM393 比较器）。它的接线是
`1=3V3 / 2=DO / 3=GND`，**只引出数字比较输出**，没有模拟通道。

这意味着它只能回答"前方 1~5cm 内有没有反光物体"，拿不到随血容积变化的连续波形。
脉率需要的是波形，不是二值量。**所以本批硬件在物理上采不到脉搏**，这不是接线或代码问题。

要真做脉率，需要 PPG 器件（如 MAX30102：I²C，红光/红外 LED + 光电二极管 + 18 位 ADC）。

## 二、于是做法分两段，边界划在"原始采样"

```
[PpgSource]  →  [PpgProcessor]  →  [屏/串口]
 mock 波形       峰值检测+脉率        真实
                ← 这一段是真代码
```

接上 MAX30102 时只替换 `PpgSource`，`PpgProcessor` 一行都不用改，
连串口输出格式、屏上排版、电脑侧解析器都不用动。

**这一轮验证的是算法和链路，不是脉搏的真实值。** 带 mock 的脉率不能当验收证据。

## 三、算法

50 Hz 采样，每 20ms 一个点。四步：

| 步骤 | 做法 | 为什么 |
|---|---|---|
| 去直流 | 一阶 EMA 高通（α=0.02，约 0.5 Hz 截止） | 呼吸和探头压力造成的慢漂移幅度比脉搏本身大，不去掉会淹掉信号 |
| 阈值 | `thr = (包络上界 + 包络下界) / 2` | 固定阈值一定失效：手指压力、肤色、环境光能让绝对幅度差好几倍 |
| 不应期 | 至少 300ms；有 3 个 RR 后收紧到中位 RR 的 0.6 倍 | 防重搏波被当成一次独立搏动（会算出整 2 倍脉率） |
| 幅度门 | `ppAmp >= 0.45 × 长期幅度` | 信号突然变小 = 接触失效。光靠不应期挡不住噪声误触发 |

脉率取 **RR 中位数**而不是均值：中位数对单次漏检/多检免疫，均值会被一个异常值拉歪。

质量分取两个因子的较小值：

- `qr = 100 × (1 − RR变异系数 / 0.25)` —— 节律稳定性
- `qa = 100 × ppAmp / 350` —— 信号幅度

`valid` 的门槛是 **质量 ≥ 40**。低于这个值 bpm 仍在跳，但不作为读数显示（屏上显示
`---bpm` 加质量分），这正是 issue #3 第 3 条要的"低质量时显示信号状态"。

## 四、实测（实机，COM4 / 115200）

用 `PPG HR <bpm>` 设定波形源的真值，再看算法估出多少：

| 真值 | 估计 | 误差 | 质量 | 有效 |
|---|---|---|---|---|
| 60 | 61.2 / 62.5 | +1.2 / +2.5 | 94~97 | 是 |
| 96 | 96.8 | +0.8 (+0.8%) | 100 | 是 |
| 120 | 115.4 | −4.6 | 100 | 是 |
| 180 | 176.5 | −3.5 | 100 | 是 |

偏差方向一致（估低），原因是波形源里叠加了 ±2.5 bpm 的呼吸性窦性心律不齐，
而 RR 中位数偏向周期较长的一侧。**不是算法误差累积**，是波形本身的性质。

三种接触状态（issue #3 第 3 条）：

| 场景 | 固件判定 | 质量 | 峰峰 | 说明 |
|---|---|---|---|---|
| GOOD | 有效 96.8 bpm | 100 | 461 | 正常接触 |
| MOTION | **无效** | 0 | 968 | 1.1Hz 大幅漂移，RR 全乱 |
| POOR | **无效** | 23~34 | 82~121 | 幅度掉到 1/8，幅度门挡住 |
| 恢复 GOOD | 有效 93.8 bpm | 94 | 478 | 自动恢复，不需要复位 |

原始采样用 `PPG LOG <秒>` 导出，每行 `PPG,<毫秒>,<原始计数>`，
电脑侧 `tools/ppg_analyze.py` 独立复算：

```
---- 元数据 ----
样本数        : 299
时间跨度      : 5.96 s
时间戳单调    : 是
采样间隔中位数: 20.0 ms (标称 20)
最大间隔      : 20 ms
疑似丢点次数  : 0

---- 峰值检测 ----
检出搏动      : 10
RR 序列       : [460, 640, 620, 620, 620, 620, 620, 620, 620]
中位 RR       : 620 ms
估计脉率      : 96.8 bpm
真值/误差     : 96.0 / +0.8 bpm (+0.8%)
```

两套独立实现（固件增量式、脚本批处理）在同一条波形上给出同一个数，
说明固件的检测不依赖某个巧合的初始化顺序。

## 五、一个值得记的坑：幅度门需要"历史"

单独截一段 POOR 的日志喂给分析脚本，会得到 **176.5 bpm、变异系数只有 0.114**，
看着像个正常的读数——但它其实是噪声凑出来的，真值 96。

原因：脚本从这段日志冷启动，长期幅度 `ltAmp` 陪着噪声一起从 0 长起来，
`ppAmp >= 0.45 × ltAmp` 恒成立，门形同虚设。固件里有"接触良好时"的历史幅度，
所以同一段数据在板上被判为无效。

**结论：相对幅度门必须有先前的正常段做参照。** 冷启动时它不起作用，
这既是它的局限，也解释了为什么不能只靠单帧判断接触质量。

## 六、命令

```
PPG                        状态：采样率 / 场景 / 估计值 / 质量 / 有效性
PPG ON | OFF               波形源开关
PPG SCENE GOOD|MOTION|POOR 切换接触状态
PPG HR <bpm>               设定波形真值（30~220），用于对照算法估计
PPG LOG <秒>               导出原始采样，每行 PPG,<ms>,<raw>，最长 300 秒
```

串口机器可读行（每秒一条）：`HR,<bpm>,<quality>,<valid>,<mock>,<stamp_ms>`

## 七、接上真器件要改什么

只改 `PpgSource::sample()`：从 I²C 读 MAX30102 的 FIFO，返回原始计数。
`PpgProcessor` 的采样率假设是 50 Hz，若器件跑 100 Hz 需要同步改 `PPG_FS` 与
`PPG_PERIOD_MS`，并把 EMA 系数按采样率重算（α 与 1/fs 相关，直接沿用会让截止频率翻倍）。

`MOCK_PPG` 位在真器件就位后应关闭，否则 `MOCK` 开关仍能在器件缺席时接管。
