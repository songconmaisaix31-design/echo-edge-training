# 语音播报与短振动（issue #4）

## 一、播放链的真实构成

本批硬件里"音频"只有 **SYN6288E** 一个模块：

```
ESP32-S3 UART2 (9600 8N1, TX=GPIO5 RX=GPIO6)
        ↓  GB2312 文本帧
   SYN6288E  内部：文本 → 合成 → 自带 DAC → 自带功放
        ↓
      扬声器（模块外接）
```

**它是"文本转语音"模块，不是音频播码器。** 输入只有两种：GB2312/GBK 编码的中文文本
帧，或少数控制命令。它不能接收 PCM/WAV 数据流。

这一点直接和 issue #4 第 1 条的验收冲突：

> 实际终端通过确认的播放链播放一段 16 kHz、16 位单声道 WAV，语音可辨认。

**在这个播放链上无法完成。** 要播 WAV 需要另配 I²S 功放（如 MAX98357A）或带 I²S 的
codec（如 ES8388），本批硬件都没有。所以这一条按现状只能标为未完成，不能用"能出声"蒙过去。

第 2 条"在板上输入一条中文文本，设备播报相应内容"是可以做的，帧格式见下。

## 二、TTS 帧格式

```
0xFD | lenH | lenL | 0x01(合成播放) | 0x00(GB2312) | data... | XOR
```

`len = 2 + data 字节数`；`XOR` 覆盖从 `0xFD` 到 `data` 末尾的所有字节。

Arduino 源文件是 UTF-8，运行期把 UTF-8 转 GB2312 不现实（要带码表），所以提示语**在编译期
就转好**，固件里直接存 GB2312 字节数组：

```c
// "图像清晰可以采集"  (16 字节)
static const uint8_t P1[] = {0xCD,0xBC,0xCF,0xF1,0xC7,0xE5,0xCE,0xFA,0xBF,0xC9,0xD2,0xD4,0xB2,0xC9,0xBC,0xAF};
```

预置 8 条，覆盖采集流程的主要提示。想加新提示语，用 `python -c "print('新提示语'.encode('gb2312'))"`
生成字节数组再登记进 `PHRASES[]` 即可，屏幕标签同时补一个 5x7 字形里有的英文短句。

## 三、振动：本批没有马达

套件里没有振动马达，所以 `GPIO4` 上什么都没接。固件照常输出电平，**只能验证时序，
验证不了"有没有震"**。这一项在 `MOCK_VIB` 打开时会被明确标注（`STAT` 里显示"无马达, mock"）。

等有马达时要注意：马达是感性负载，不能直接挂 GPIO —— 需要三极管/MOS 驱动 + 续流二极管，
额定电压按马达铭牌，不要从 3V3 取电（启动电流会把 MCU 拉复位）。

## 四、这一轮真正修掉的问题：执行器动作打断采样

issue #4 第 4 条要的是「播报和振动分别开启时记录丢样数」。为此在固件里加了采样槽监控
（`JITT` 命令）：以主循环迭代间隔为判据，标称 20ms（PPG 一个采样槽），超过 30ms 算迟到，
按 `间隔/20 - 1` 折算丢了几个槽。

第一次测就抓到两个真问题：

### 问题 1：振动用 `delay()` 阻塞

```c
// 老实现
digitalWrite(PIN_VIB, HIGH);
delay(ms);              // ← 这 150ms 里主循环完全停转
digitalWrite(PIN_VIB, LOW);
```

150ms 正好吞掉 7 个采样槽。改成置高后记结束时刻、由 `loop()` 负责拉低：

```c
digitalWrite(PIN_VIB, HIGH);
vibEndMs = millis() + ms;
```

### 问题 2：`fireHint()` 里同步刷屏 + `Serial2.flush()`

一屏 1024 字节走 I2C@400k 约 25ms；22 字节 TTS 帧在 9600 下 `flush()` 又等 23ms。
两者挤在同一轮迭代里，间隔叠到 67~100ms，一次丢 2~4 个槽。

改法：`fireHint()` 只置 `drawPending`，重绘在循环末尾做，且**刚处理过命令的那一轮不重绘**，
把"播报"和"刷屏"拆到两轮迭代里，各自 25ms 以内；`Serial2.flush()` 直接去掉
（22 字节远小于 256 字节 TX 缓冲，秒级间隔不会溢出）。

## 五、A/B 实测（实机，COM4 / 115200，每轮 20 秒）

| 场景 | 折算丢样 | 丢样率 | 最大间隔 |
|---|---|---|---|
| A 基线，无动作 | 0 / 1050 | 0.00% | 34 ms |
| B 阻塞振动 150ms ×10（老实现） | **62 / 1079** | **5.75%** | **183 ms** |
| C 非阻塞振动 150ms ×10 | 0 / 1080 | 0.00% | 34 ms |
| D 播报 TTS ×10 | 0 / 1131 | 0.00% | 35 ms |
| E 完整提示 HINT ×10（改前：同步刷屏 + flush） | 23 / 1131 | 2.03% | 100 ms |
| F 完整提示 HINT ×10（改后：延迟重绘 + 不 flush） | **0 / 1129** | **0.00%** | **34 ms** |

基线里那 55 次"迟到迭代"是每秒一次的全屏刷新（34ms），**不构成丢槽** —— 因为
采样是按 20ms 固定步进补的，34ms 只够补 1 个槽。这个区别很重要：
"间隔变大"和"丢样"不是一回事，判据要落到槽数上。

## 六、验收状态（对应 issue #4 四条）

| # | 验收项 | 状态 |
|---|---|---|
| 1 | 通过播放链播 16kHz/16bit 单声道 WAV | ⛔ **做不到**：SYN6288E 只吃 GB2312 文本帧，无 I²S 通道 |
| 2 | 板上输入中文文本，设备播报 | 🟡 帧格式与发送已验证（22 字节 / XOR 正确）；**模块无回传，实际发声未验证**（需人耳确认） |
| 3 | 按马达类型接入并触发短振动 | ⛔ 无马达，只能验证 GPIO 时序 |
| 4 | 播报/振动开启时记录丢样并与基线比较 | ✅ 见上表，且据此修掉两处阻塞 |

## 七、`JITT` 命令

```
JITT          打印：窗口、应采样槽、迟到迭代、折算丢样、最大间隔、振动次数
JITT RESET    清零重新计
VIB <ms>      非阻塞振动
VIBB <ms>     阻塞版（保留下来做 A/B，会打断采样）
```

做对照实验时：`JITT RESET` → 跑 20 秒 → `JITT`，两次之间不要改固件。
