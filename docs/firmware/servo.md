# 双舵机与电源（issue #5）：本批做不了，先把手上的信息锁死

## 一、结论先行

本批实物**没有舵机、没有舵机控制板、没有独立 5V 稳压电源**。issue #5 的四条验收
全部依赖实物动作与电流测量，一条都无法完成。

所以这份文档不做"看起来做了"的交付。它做三件在没实物时仍然有价值的事：
把套件官方定义里的参数和告警固定下来、把电流预算算清楚、把接上实物时的操作顺序写死，
免得下次拿到舵机时重复踩坑。

**固件侧只有一条 `SERVO <1|2> <deg>` 命令，做角度→脉宽的换算与打印，不构成任何验收证据。**

## 二、接口（来自套件 `modules/mg90-servo-controller`）

| 项 | 内容 | 来源 |
|---|---|---|
| 连接器 | CN2：`1=PWM1` / `2=PWM2` / `3=GND` | module.json `pin_numbers` |
| 逻辑电平 | 3.3V PWM，50 Hz 帧 | 本固件 `ledcAttach(pin, 50, 16)` |
| 舵机电源 | **独立 5V 供电端**，与控制板共地 | notes 原文 |
| 转接电路 | 「无源信号直连与电源并联分配，**未配置有源控制和稳压电路**」 | programming_facts |
| 状态 | `connection_status: schematic-derived; physical orientation unverified` | module.json |

两条必须记住：

1. **「不要将 PWM 当电源」**（原文）。PWM 只出信号，舵机电流走独立端子。
2. 既然没有稳压，"5V 电源质量"就等于"舵机表现"。电源纹波和压降会直接变成抖动。

## 三、舵机本体（来自 `modules/mg90s-servo`）

| 项 | 内容 |
|---|---|
| 型号 | MG90S，**模拟舵机**（与 MG90 数字舵机不同） |
| 版本 | 商家提供 **90° / 180° / 360°（连续旋转）** 三种规格 |
| 控制死区 | 5 µs（商家表格标注） |
| 脉宽 | **未确认** |
| 机械限位 | **未确认** |
| 状态 | `connection_status: blocked`，原文「具体运动版本、线色/针号、脉宽和机械限位待确认」 |

### ⚠️ 最容易出事的一条：360° 版本

如果手上是 **360° 连续旋转版**，它不认角度：脉宽 1.5ms 附近是停转，偏离越多转得越快，
**不会停在某个角度上**。这时候任何"限位保护"都是假的 —— 发 0°/180° 它会一直转。

所以接实物前第一件事是确认版本，而不是先写代码。确认方法：发 1.5ms 应该静止；
发 1.0ms 和 2.0ms，如果它是**匀速转**而不是"转到某个位置停住"，就是 360° 版。

## 四、电流预算

MG90S 的堵转电流商家没给精确值，下面按公开资料里最常见的量级估算，**标注为待实测**：

| 工况 | 单只 | 两只 |
|---|---|---|
| 空载待机 | ~10 mA | ~20 mA |
| 空载转动 | ~100 mA | ~200 mA |
| 堵转（峰值） | ~700 mA @4.8V | **~1.4 A** |

据此的电源要求：

- **5V / ≥2A 独立稳压**，与 ESP32-S3 共地
- 峰值 1.4A 是"两只同时堵转"的极端值；同时启动的浪涌通常低于堵转，但持续时间更长
- **禁止**从 ESP32 的 3V3 或 USB 口取电：USB 口限流 500mA，启动浪涌会把主控拉复位

ESP32-S3 自身：WiFi 峰值约 240mA，本固件不开 WiFi，实测运行电流约 60~80mA。
所以"主控被舵机拖低压复位"是这个项目里最典型的故障模式，**主控和舵机必须分开供电、只共地**。

## 五、电池与充电器（issue #5 第 4 条）

套件里确实有 `modules/battery-charger`：**12V 锂电池充电器 V1**。但它的状态是 `blocked`：

> 无软件接口；**电池串数、充电电压电流、插头极性须由供货方确认后使用。**
> `connector: None`，`pin_numbers: {}`

也就是说：图纸只有 `SCH_12V锂电池充电器_2026-10-12.pdf`（原件不随包），
**没有任何一项电气参数被确认**。在这种情况下接线，风险是烧电池或烧充电器。

接电池前必须拿到并记录的四项（否则不许通电）：

1. 电池化学体系与串数（如 3S Li-ion = 11.1V 标称 / 12.6V 满电）
2. 充电器铭牌输入（AC 电压/频率）与输出（电压/电流）
3. 插头极性（正负内芯）—— 用万用表量，不要看线色
4. 是否带过充/过放保护板

舵机的 5V 从哪来也没定：如果要"单电池供电整机"，需要一级 12V→5V 降压（≥2A），
这一级在套件里同样没有。所以"接电池"这件事，实际上还缺一个 DC-DC。

## 六、接上实物后的操作顺序（照做，别跳）

```
1. 确认舵机版本（90/180/360），量脉宽：先发 1.5ms 看是否静止
2. 单独给舵机供电，共地，不接主控信号，确认供电电压 5.0V±0.1
3. 接 PWM 信号，发小角度（如 85°/95°）确认方向与行程，逐步扩到 0/180
4. 记录方向：写清哪个通道顺时针、哪个逆时针
5. 单只空载测到达时间，与 0.1s/60° 对标
6. 两只同时启动，用万用表盯 5V 轨，记录跌落到多少毫伏
7. 全程确认主控不复位（看串口有没有重启横幅）
8. 最后才接电池，且先把第 5 节的四项参数记录完整
```

## 七、固件现状

`EdgeTerminal.ino` 里只有：

```c
SERVO <1|2> <deg>    # 角度 -> 脉宽 -> 占空比，打印计算值
```

PWM 在**第一次收到命令时**才 `ledcAttach`，不在开机时占用引脚 —— 本批没有舵机，
开机就配 PWM 只会让 `PROBE` 类诊断看到莫名其妙的电平。

角度换算：`pulse = 500 + deg/180 × 2000`（µs），帧长 20ms，16 位占空比。
`GPIO7` / `GPIO15` 分别对应 CH1 / CH2，都避开了 UART0（43/44）、Flash（26~37）、USB（19/20）。
