# Mock 数据层：在没有器件的情况下把链路跑通

这份文档说明 `firmware/edge-terminal/` 里的 mock 是怎么工作的、哪些数据是编的、
以及怎么一眼分辨。**任何一份带 mock 数据的截图或日志，都不能当作硬件验收证据。**

## 一、为什么 mock 放在数据源，而不是显示层

如果只是往屏幕上塞几个假数字，验证的是 `printf`，不是链路。所以 mock 的位置在
**器件本该给出的原始量**这一层：

```
mock 就在这一层
      ↓
[Mock] → [量程换算/CRC/补偿] → [有效性判定] → [屏刷新] → [串口帧] → [电脑解析]
                    ↑ 以下全部是真实代码路径
```

这样做的直接好处：换回真器件时，`EnvHub::poll()` 里的分支判断、有效性传播、
屏上角标、CSV 字段顺序、电脑侧解析器——全都不需要改，因为这一轮已经把它们跑通了。

## 二、三条硬规则

| 规则 | 实现 | 意义 |
|---|---|---|
| 器件优先 | `EnvHub::poll()` 里 mock 的条件是 `!present && !everSeen` | 真实器件一旦应答，mock 立刻退出，绝不覆盖真实读数 |
| 每个值带 MOCK 位 | 屏上 `M` 角标 / 串口 `[MOCK:..]` / CSV 第 9 列 | 任何消费方都能分辨这条数据是编的 |
| 只造采样，不造结论 | 脉率等有算法的量由正式算法从 mock 波形算出 | 算法本身的正确性可以被这轮验证覆盖 |

第三条是分开写的重点：`MOCK` 不会直接返回"心率 96 bpm"，它返回的是 ADC 采样序列，
bpm 由峰值检测算法算出来。所以如果算法有 bug，mock 下同样会算错——这正是我们要测的。

## 三、命令

```
MOCK                      查看状态：每个源当前是"实物在线 / MOCK 接管 / 无数据"
MOCK ON | OFF             环境三项全开 / 全关
MOCK TEMP ON | OFF        单源开关，支持 TEMP / RH / PRES / ENV / ALL
MOCK BASE 21.5 55 1008    改基线（温度 °C、湿度 %RH、气压 hPa）
```

`MOCK ON` 只打开**本固件已实现**的源（见 `mock_sources.h` 里 `MOCK_ALL` 的定义），
不会把还没实现的位一起点亮。

## 四、串口格式变化

人读行只是在行尾多了个标记，字段没动：

```
[ENV] #12 t=24.38 C  rh=47.09 %  p=1013.37 hPa  [MOCK:T RH P ]
```

CSV 行**新增第 9 列** `mock_mask`（位图：1=TEMP 2=RH 4=PRES）：

```
ENV,24.38,47.09,1013.37,1,1,1,7732,7
                              ^ 三项都是 mock
ENV,0.00,0.00,0.00,0,0,0,5312,0
                            ^ mock 关闭且无实物 -> 三列有效性全 0
```

读前 8 列的老解析器不受影响。新增字段一律往**尾部追加**，这是这个项目后续所有
串口格式变更的统一约定。

## 五、当前哪些是 mock 的

| 数据 | 来源 | 说明 |
|---|---|---|
| 温度、湿度、气压 | **MOCK** | 本批实物没有 GXHT30C 和 BMP388 模块 |
| OLED 显示 | 真实 | SSD1306 0x3C，实拍确认 |
| 中文播报 | 真实 | SYN6288E 帧通过 UART2 发出，模块无回传故只听不看 |
| 红外 DO | 真实 | ITR9909 数字输出，实测恒 0（未接或未反射） |

## 六、怎么验证"不是靠 mock 通过验收"

关掉 mock 看降级：

```
MOCK OFF
READ
```

预期（已实测）：

```
[ENV] #8 t=-- C  rh=-- %  p=-- hPa  [TEMP 离线] [RH 离线] [PRES 离线]
ENV,0.00,0.00,0.00,0,0,0,5312,0
```

屏上对应三行变成 `--` 加叉号角标。这就是 issue #2 第 4 条验收要的状态：
**单独断开任一传感器，该项显示不可用，其余继续刷新。** mock 关掉时三项全灭，
正好证明这个"不可用"不是画上去的，而是有效性标志真的被清零了。

## 七、已知限制

- mock 的随机源是固定种子的 xorshift32，**同一上电时序完全可复现**。这是刻意的
  （便于对比两次运行），但也意味着连续两次上电的曲线会一模一样，别当成"数据太规律"。
- mock 值不会超出传感器量程，也不会模拟 CRC 错误、总线死锁这类故障。故障注入
  要用 `MOCK OFF` + 拔线，别指望 mock 覆盖。
- `MOCK BASE` 改的是基线，慢漂移分量仍会叠加，实测值不会精确等于设定值
  （例如设 21.5 读到 21.88，因为 +0.6 的正弦分量当时正在高位）。
